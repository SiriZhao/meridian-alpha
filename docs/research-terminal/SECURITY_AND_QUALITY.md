# Research authority, threats and quality

| Layer | Allowed | Cannot grant |
|---|---|---|
| Historical/provider source | Timestamped observations with provenance | Execution certification from public entitlement-unknown data |
| Deterministic Quant | Factors, ranks, regime and constrained shadow targets | Calibrated profit probability, live authority or automatic promotion |
| What-if | Sanctioned input weights, hard-risk caps, declared shock sensitivity | Orders, fills, account initialization or inferred holdings |
| GPT primary/skeptic/scenario/synthesis | Citation-bound interpretation, contradictions and conditional prose | Editing scores, risk limits, quantities, limits or broker authority |
| Skill/planner/MCP | Fixed workflow, typed read-only calls and evidence navigation | Application authorization or source-instructed installation |
| Human/canonical process | Independent review under existing account/quote/risk/host gates | Treating a research action as an observed fill |

## Threat model

All source strings, filings, events, tool results and descriptions are untrusted
data. The planner has no text-to-shell/tool dispatcher. Extra request fields,
invalid symbols, duplicate identities, future/naive metadata, nonfinite weights,
wrong-account contexts and unbounded histories fail before calculation. Fixed
tool names and versioned workflow contracts reject unknown installation or
execution actions. No third-party server or Skill is installed.

Hash/cutoff mismatches and replayed trace IDs refuse cross-snapshot citations.
Native schemas enumerate evidence IDs; exact numerical citations resolve JSON
pointers against supplied structured records and compare source-native values.
An invented number, fake ID or unchecked numerical role prose rejects the model
response. GPT errors retain the original Quant packet. Model scenario values
remain UNCALIBRATED; decision briefs return null probabilities and no manual
action. Brief assembly also checks numerical evidence against the source packet.

The compact model view validates nested score/factor/regime cutoffs, factor
availability, symbol/policy identity and eligible score/rank correspondence.
Cache identity includes the hard RiskPolicy hash as well as challenger policy,
engine and input. A policy change during calculation refuses sealing.

This is defense in depth, not a claim to solve all prompt injection. A malicious
source can still contain misleading prose. Exact numeric equality does not prove
the financial meaning of a claim, provenance authenticity or proper unit choice.
Caller certified-history tags are attestations, never automatic approved OOS
eligibility. Cross-provider conflicts remain refusal evidence in existing gates.
The terminal does not broaden native child-process permissions or promise that
natural-language instructions alone enforce filesystem security.

Account fields are excluded from serializable what-if requests, not cached and
not echoed in results. No prompts/private account dumps or credential values are
logged/committed. The three new MCP tools do not call providers, stores, model
processes or order planners. Tests use isolated fixture accounts and runtime roots.
Existing manual-authority and paper regressions must continue passing.

## Research quality scorecard v1

Measure source count, cited-claim count, evidence coverage, skeptic challenge and
contradiction counts, unresolved disagreement, success/failure completeness,
deduplicated model wall time and observable token usage. Cost and time saved
remain unknown until measured. Compare a Quant-only brief and Quant+GPT brief
on the same sealed evidence; record changed evidence coverage/contradictions and
human review duration under an independent protocol. No such controlled live
benefit evaluation was completed by engineering tests. Do not claim improved
returns, win rates, decision quality or review efficiency from fluent prose.

The original numerical engine and frozen V2/V2.2 archives are unchanged.
Real financial evaluation remains a separately qualified walk-forward/forward
research task, with original cost/dependence/survivorship limitations retained.

Read-only SQLite inspection rejects WAL headers and journal sidecars before
queries. It does not checkpoint, change mode or assume that an active database
is immutable. Explicit journal-review refusal differs from corruption and
migration status. A concurrently reconfigured database requires OS-enforced
read-only access; the header guard is not a general filesystem sandbox.
