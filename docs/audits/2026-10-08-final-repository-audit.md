`codex/canonical-truth-hardening`, origin
`https://github.com/SiriZhao/meridian-alpha.git`. Initial working tree clean.

## Defects and repairs

| Finding | Repair | Regression evidence |
|---|---|---|
| Wrong-shaped evidence JSON could raise AttributeError | Validate envelope/list shape before field access | Nine corruption/cache-miss cases |
| Provider-health connection context did not close the connection | Explicit `closing` plus transactional context | Closed handles after success and SQL failure |
| Concurrent paper launches could race beyond SQLite's fill guard | Serialize full account lifecycle with OS lock | Contention stops before research; no fill mutation |
| Old JSON stores could lose another instance's writes or retain failed mutations | Writer lock, durable reload, atomic write and memory rollback | First-seen/replay/shadow stale-instance and denied-write cases |
| Fixed staging names and missing fsync in reports/caches/snapshots/replay | Exclusive UUID staging and shared atomic primitives | Original bytes retained on replace failure; no false complete receipt |
| Mature legacy shadow outcomes always hit immutable-row rejection | Allow one validated outcome join, then freeze it | Valid/repeated join, contradictory join and nonfinite rejection |
| Empty or new legacy health statuses were green | Unknown/degraded health is yellow and blocks manual entry | Empty, NOT_RUN and unrecognized status cases |
| Malformed lock/receipt envelopes had misleading exception types | Explicit fail-closed error categories, preserve corrupt ownership | Corrupt lock and receipt matrix |
| Skill build included local bytecode and had direct ZIP writes | Exclude generated bytecode, refuse unsafe paths, atomic archive/sidecar publication | Deterministic archive and sensitive filename cases |
| Source review could include nested clones/runtime sidecars and delete previous archive first | Exclude generated/private/runtime paths; atomic archive replacement | Windows synthetic archive creation/replacement smoke |
| CI floated dependency versions and exposed matching secret text | Frozen uv 0.12.7 installation; filename-only scan | Independent install and Windows/Linux CI contract |

Tests that injected failures using old temporary filenames now inject failures
at final Markdown replacement. Their failure and identity assertions are
unchanged; no skip, xfail or assertion reduction was introduced.

## Remote acceptance contract

An independent directory is cloned from GitHub, not copied from the development
tree. Python 3.12 creates its own environment. uv 0.12.7 installs the frozen
lock with fresh caches; dependency integrity is checked with ensurepip/pip.
No inherited PYTHONPATH, policy directory, reports or runtime are used.
After final push, this clone advances only from the published branch and runs
the complete validation entrypoint, Skill archive validation and Windows
packaging smoke. Acceptance requires its HEAD to match local/remote HEAD.

CI retains Python 3.12 Ubuntu/Windows coverage, runs the same full entrypoint,
keeps manual-authority and replay-integrity checks, builds/extracts/validates the
portable Skill, uploads only that validated archive and checksum, and runs the
Windows review-packaging smoke. Final workflow acceptance is checked against
the published SHA, never inferred from a previous green workflow.

## Safety and practical limits

No real broker credentials, permission integration, live orders or live fills.
Production trading logic, sizing, risk limits and research weights unchanged.
Legacy health authorization is stricter for missing/degraded observations.
Public research quotes stay uncertified; provider health never chooses routing.
Research remains advisory. Forward evidence remains shadow-only with no
automatic promotion. The persistent canonical runtime was not modified.

No distributed/network-filesystem crash guarantee, queued concurrency or power
loss certification is claimed. Incomplete report bundles fail closed while
ledger ownership remains authoritative. Live GPT/regular-session acceptance
and mature verified forward samples require separate operational evidence.
Dependency integrity and locked installation are not an exhaustive third-party
vulnerability assessment. Long modules and function-local dependency cycles
remain technical debt; startup imports and top-level graph are validated.
